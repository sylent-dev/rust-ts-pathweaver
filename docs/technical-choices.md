# Technical choices

The libraries, the services and the main designs of Pathweaver, with their reasons and the alternatives rejected. Written with the skeleton on 2026-11-16; completed at step 0 on the same day.

| Subject | Choice | Reasons |
|---|---|---|
| Shape of the application | A website: the core in Rust compiled to WebAssembly, the interface in TypeScript with Svelte 5 and SvelteKit, as in Stepwise | Version 3 is a platform of shared builds: pages with their own address, found by search engines, text to select and to read with a screen reader, which HTML gives and a canvas doesn't. Compared on 2026-11-16, and rejected: the whole application in Rust with egui compiled to WebAssembly (one language, but everything drawn in a canvas: no pages to index, weaker text editing and accessibility, several megabytes to load), fitting a viewer alone but not the platform. The workspace, its checks and the bridge are those of Stepwise, already tried. |
| Bridge | `crates/wasm`, with `tsify` and `serde-wasm-bindgen`: a type of its own for each thing that crosses, its TypeScript type generated from it; under each exported function, a function in plain Rust that `cargo test` calls | As in Stepwise (see its `docs/technical-choices.md`, Bridge): the two sides can't drift, and the crates of the core know nothing of JavaScript. |
| Reading the `.build` files | `serde` and `serde_json` in `crates/build-file`, with `preserve_order`; every object keeps the fields the format doesn't name in `extra` (`#[serde(flatten)]`), an entry keeps the form it was written in (its id alone or an object, one level or a list), and a field the format lets leave out is absent, `null` or a value (`Nullable`), not an `Option`, which writes nothing back for a `null` | The format is experimental and will change: a file written by another tool, or by a later version, is written back as it was read. |
| Errors of a file | A refused file gives an error made of data, its kind and its values (the line, the field), never a sentence: the interface writes it in each language. The place of a value of the wrong type comes from `serde_path_to_error` (by the author of `serde`, MIT or Apache 2.0, a few hundred lines, no dependency of its own), and an entry is read by hand (a string its id alone, an object its fields) rather than by `#[serde(untagged)]`, which tries each form and keeps only « no form matched » | Measured on 2026-11-22: `serde_json` alone names the line of a wrong value, not its field; an untagged entry gives `skills[0]` for a wrong id in a support of that skill, the entry read by hand `skills[0].support_skills[0].id`. |
| Key of a content | FNV-1a on 64 bits, written in the core, of the build read and written again without spaces, the fields of each object sorted by name, as 16 hexadecimal digits | The same build pasted on one line and opened from its file is one build (`specs.md`, Opening builds). Sorted, since the core writes the fields it names in its own order, whatever the order of the file: the order of the file would count for the fields it doesn't name only. No dependency for ten lines, and the same key from one version of Rust to the next, which the library (step 8) will keep. A file made on purpose with the key of another only shows the build already open in its place. |
| Game data | The passive tree, the ascendancies and their portraits exported by Grinding Gear Games, the rest (gems, uniques, base items) from RePoE; converted once per version of the game by a script in TypeScript, `web/scripts/game-data/` (`npm run game-data`), into compact files committed in `web/src/lib/game-data/<version>/`, one folder per language for the texts; read by the interface (`game-data.ts`), which Vite gives each file under a name made from its contents, loaded when a build first needs it (4d, the owner, 2026-11-22) | The only official export is the tree; RePoE is the export of the files of the game that tool developers use, and every id of the corpus is found in the two. Served by Pathweaver, so that the website doesn't depend on them at run time. The script in TypeScript, as `build-wasm.ts`, so that the lint, the types and the tests of the CI check it, and the types of the files (`format.ts`) are written once for the script and the page; rather than Python (the script of the mock-up, which the CI doesn't check) or Rust (an HTTP client and a crate for a tool run once a version). Read by the interface rather than the core: a name found by its id is no rule, and the one rule of the data, the colour of a gem, is applied by the script; the core reads the data of the tree when it needs them (5a). Rejected: Path of Building (Lua made for its calculations), poe2db.tw (no API). See [game-data.md](game-data.md). |
| Passive tree | Its data in a crate of the core (graph, positions, which passives apply at a level); drawn by the interface in a canvas (Canvas 2D), with the icons and frames of the tree export, drawn from their sheets | 5,153 nodes: too many for SVG, a few for a canvas. The icons and frames of the passives come from the game (the owner, 2026-11-18, see [game-data.md](game-data.md)). Measured on the mock-up (2i3, 2026-11-20), the whole tree drawn again at every frame of the screen, on the owner's screen (2,560 × 1,440, a window of 1,600 × 1,000): 152 frames per second while it is dragged, 2 ms of script per drawing, and about 100 with the whole tree on screen, zoomed out (2i4, 2026-11-20); the simple drawing is enough, without a cached image or WebGL, which step 5b adds only if the application measures worse. |
| Levels and merging | In the core: which entries apply at a level, the markers where the build changes, what changes at a marker, the merging of the builds of a guide and its checks (Merge .build, after version 1). What a build holds at a level is read thing by thing, each once whatever the entries that set it (`Build::at_level`); the changes compare two levels, and the markers are the levels with a change other than passives taken, never a comparison of their own (`Build::changes_by_level`, `Build::markers`). Only the levels where an entry starts or has just stopped are read, and each thing is found in a sorted table, never by searching a list: a file of 1 MB made to cost is read in less than a second, where 90 KB took 6 (`changes/large_files.rs`, the review of 4c). The bridge gives the levels and the markers of a build when it opens; the changes and the invalid intervals cross with the steps that show them (4h, 4i) | Rules of the format, tested with `cargo test` on the corpus, and needed by the server of version 3 to check a published build. |
| Share link | Out of version 1 (the owner, 2026-11-18): a build is shared as its `.build` file. A link that holds the build (the JSON without its spaces, compressed with deflate, in base64url after the `#`) is no link for a chat; a short link, its key only, stored by the server of version 3 | Measured on the corpus: 1,936 characters for the median build, 7,348 for the longest; 1,562 and 3,142 without the notes of the author. A Discord message stops at 2,000. |
| Library | The open builds kept in IndexedDB, through a small module of the interface | No server and no account; IndexedDB holds files of any size, unlike `localStorage`, and the browser may refuse it (private browsing), which the interface handles. |
| Host | Cloudflare: the static website first, as a Worker of static assets without code at `pathweaver.sylent.tools`, deployed by GitHub Actions with `wrangler deploy` at each merge into `main` (the owner, 2026-11-22); then the code of that Worker (Rust with `workers-rs`), D1 and R2 for version 3. See [cloudflare-usage.md](cloudflare-usage.md) | The owner's domains and the Workers of Exile Market are already there; no machine to administer; the static files are free, and the free plan stops at its quotas rather than bill. Compared on 2026-11-16, and rejected: a VPS (cheaper than a managed platform, but its updates, firewall and backups by hand), a managed platform such as Fly.io (more expensive, for the same absence of administration). A Worker rather than Cloudflare Pages (compared on 2026-11-22): the same files served the same way and free, but Cloudflare names Workers its main platform for new projects, gives it the logs, the scheduled tasks and the limits of requests that Pages lacks, and version 3 then grows the same project rather than moves it; Pages keeps finer previews of the branches, which the deployment doesn't use. Built by GitHub Actions rather than on Cloudflare, since the build needs Rust and `wasm-bindgen`, already set up for the CI. |
| State of the interface | What belongs to one component stays in it (a hover, a drag under way, a field being typed). What several components read has one source, a module of `web/src/lib/page/` that they all read and none copies: the open builds, the one shown (none on the library) and the level of each (`open-builds.svelte.ts`); which window or menu is open, one value (`popup.svelte.ts`), never a boolean per window. The keys and the clicks heard anywhere on the page are wired once, by the layout (`page-events.ts`), and what a key asks for is decided by one function that never touches the page (`page-keys.ts`). A build is named by the key of its content, never by its object nor by its place in the list; the list of the builds is a `$state.raw`, replaced whole when a build opens or closes, and only the level of each build, kept apart by key, changes in place. What changes the build shown without a click (files dropped) closes the window or the menu open (`popup.close()`), and so does the component whose trigger leaves the page (« +N ▾ » once every tab fits) | A rule of 2026-11-19, after three bugs of the mock-up, which kept a boolean per window and a level per band: « +N ▾ » opened in every band at once, « 3 changes » showed it, and each fix added a line that closed the other window. With one value, two windows can't be open by construction, and a new window (the box of Download .build) is one more name, not one more pair of lines. The key rather than the object, and `$state.raw` for what the core has read: Svelte hands back a `$state` object wrapped in a proxy, it and all it holds, which isn't equal (`===`) to the object it was given and costs at each reading of a build nobody changes. The tests of the state (`*.svelte.spec.ts`) run compiled as for a browser, in Node without a page, as in Stepwise (`web/vitest-node-client.ts`), and read the state in an effect: a test that reads a value right after writing it would pass on a plain field. `page-events.ts` reads real events of a browser and has no test until the interface has a test environment with a page (step 4e). |
| Interface texts | Fluent, in `web/locales/`, as in Stepwise | A language is added without touching the code. |
| Front-end tooling | npm, TypeScript strict, `svelte-check`, ESLint, Prettier, Vitest, as in Stepwise | The configuration every Svelte developer knows, checked in the CI next to Clippy and `cargo test`. |
| The owner's screen | 2,560 × 1,440 pixels (WQHD), noted on 2026-11-16 at step 2 | The mock-up is checked at the smallest width (900 pixels, half of a 1920-pixel screen) and at the owner's, where the page shows wider layouts (the side panel from about 1,400 pixels). |
| Mock-up server | `python3 docs/mockups/serve.py 8796`, from the repository root (`html-mockups` skill) | A port of its own, unused by the owner's other projects (8742, 8753, 8765, 8770, 8781 and 8790 are taken), so that two mock-up servers never take each other's port; no cache, so that a reload never mixes old and new files. |
| Font of the name | Archivo by Omnibus-Type, in its weight 700, spaced -0.06 em, the same in every style; under the SIL Open Font License 1.1 (checked on 2026-11-17 in `ofl/archivo` of the `google/fonts` repository); the website serves its file itself | Chosen by the owner on 2026-11-17 among 132 fonts of Google Fonts tried on the name. The license allows embedding and serving the font with the website, on condition that it isn't sold on its own and keeps its license. |
| Font of the interface | Manrope by Mikhail Sharanda, for the text, the titles (600, spaced -0.02 em) and the numbers, in its figures of one width so that the levels line up; the same in every style; the code (a pasted JSON, the line of an error) in the monospace font of the system, which costs no download; under the SIL Open Font License 1.1 (checked on 2026-11-18 in `ofl/manrope` of the `google/fonts` repository); the website serves its file itself | Chosen by the owner on 2026-11-18 among 85 fonts of Google Fonts under that license, tried on the page of a build and the library: already the font of the links of the band of the site, one font for every role keeps a single voice beside Archivo and one file less to load; its tabular figures do what a monospace font would for the numbers. |
