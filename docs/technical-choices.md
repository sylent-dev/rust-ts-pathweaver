# Technical choices

The libraries, the services and the main designs of Pathweaver, with their reasons and the alternatives rejected. Written with the skeleton on 2026-11-16; completed at step 0.

| Subject | Choice | Reasons |
|---|---|---|
| Shape of the application | A website: the core in Rust compiled to WebAssembly, the interface in TypeScript with Svelte 5 and SvelteKit, as in Stepwise | Version 2 is a platform of shared builds: pages with their own address, found by search engines, text to select and to read with a screen reader, which HTML gives and a canvas doesn't. Compared on 2026-11-16, and rejected: the whole application in Rust with egui compiled to WebAssembly (one language, but everything drawn in a canvas: no pages to index, weaker text editing and accessibility, several megabytes to load), fitting a viewer alone but not the platform. The workspace, its checks and the bridge are those of Stepwise, already tried. |
| Bridge | `crates/wasm`, with `tsify` and `serde-wasm-bindgen`: a type of its own for each thing that crosses, its TypeScript type generated from it; under each exported function, a function in plain Rust that `cargo test` calls | As in Stepwise (see its `docs/technical-choices.md`, Bridge): the two sides can't drift, and the crates of the core know nothing of JavaScript. |
| Reading the `.build` files | `serde` and `serde_json` in `crates/build-file`, with `preserve_order`; every object keeps the fields the format doesn't name in `extra` (`#[serde(flatten)]`), and an entry keeps the form it was written in (its id alone or an object, one level or a list) | The format is experimental and will change: a file written by another tool, or by a later version, is written back as it was read. |
| Passive tree | Its data in a crate of the core (graph, paths, order of the passives by level); drawn by the interface in a canvas (Canvas 2D) | About 5,100 nodes: too many for SVG, a few for a canvas. To decide at step 0, with the sources of the data. |
| Host | Cloudflare: the static website first, then Workers (Rust with `workers-rs`), D1 and R2 for version 2 | The owner's domains and the Workers of Exile Market are already there; no machine to administer; the static files are free, and the free plan stops at its quotas rather than bill. Compared on 2026-11-16, and rejected: a VPS (cheaper than a managed platform, but its updates, firewall and backups by hand), a managed platform such as Fly.io (more expensive, for the same absence of administration). |
| Interface texts | Fluent, in `web/locales/`, as in Stepwise | A language is added without touching the code. |
| Front-end tooling | npm, TypeScript strict, `svelte-check`, ESLint, Prettier, Vitest, as in Stepwise | The configuration every Svelte developer knows, checked in the CI next to Clippy and `cargo test`. |
