## Merge .build: first after version 1

The owner, 2026-11-21, at step 2k5: set aside from version 1, the first item once it is online. A tool of its own beside the viewer, **Merge .build**, a link of the band of the site just after My library: a merge is done once to prepare a guide, not while reading a build.

- **Why it matters**: Mobalytics, 16 files of the 32 of the corpus, exports a guide as one file per range of levels (3 guides of the corpus: Flameblast in 7 files, Varashta in 3, Ice Shot in 3), each a snapshot whose entries say 1–100 (see [build-files-in-the-wild.md](build-files-in-the-wild.md)). Opened alone, `lvl 15-32` shows at level 80 the tree of level 32, without a word. Other tools already write a guide as one file with real windows of levels (a campaign of poe2-tools, the leveling of Maxroll), which Pathweaver reads as it is.
- **The tool takes the files themselves**: the files of the guide dropped on its page, their start levels set, and only the merged guide opens in the viewer or downloads as a `.build`, rather than opening each file as a tab first and merging the tabs.
- **A bridge from the viewer** (an idea of Claude Code, kept by the owner): someone who opens `lvl 15-32` in the viewer won't know the tool is there, a link of the band isn't enough. When the name of a file reads as a range (« lvl 15-32 »), a quiet line « A part of a guide in several files? Merge .build » leads to it; it replaces the line once planned under the band of the open builds when several open builds share their `link` and their ascendancy.
- **The band of the site with three links on the left**: it fits at 960 and at 1,920 pixels; check it at the narrowest window (900 pixels) when the tool is drawn.
- **Its name**: « Merge .build » (the owner), in answer to « Download .build » and short enough for the band; « Merge a guide », which says better what it is for, set aside. The page of the tool says what it does in its title.
- **The rules specified before**, the section Merging a guide of `specs.md` until 2026-11-21, to start from:
  - The user picks several builds and merges them; or completes a merged guide with one more build, for lower or higher levels.
  - A screen lists the builds in the order of their levels, each with the level it starts at, guessed from its name (`lvl 15-32` starts at 15) and editable; a build whose level can't be guessed is asked for.
  - Each build applies from its start level to the level before the next one; the last one up to 100.
  - Checks before merging:
    - **Overlap**: two builds that start at the same level block the merge, which shows the level in conflict, until a start level is changed or a build removed.
    - **Gap**: the first build starting above level 1 is a warning (nothing is shown below it), not a block.
    - **Different guides**: builds with different `link`s or ascendancies are a warning (« these builds don't seem to come from the same guide »), not a block.
  - The merged guide is one build: each entry applies over the levels of the builds that hold it, within its own `level_interval` if it has one, cut at the limits of each build. The name is that of the first build without the part its level was guessed from (« lvl 1-14 - 0.5.5 Fubgun Flameblast Oil G » gives « 0.5.5 Fubgun Flameblast Oil G »), and the author is that of the first build; both are editable.
  - A build whose level can't be guessed (« Endgame - … ») blocks the merge until its start level is typed.
  - The merged guide joins the list of open builds; the builds it comes from stay open.
  - The page of the tool, as specified for « Merge… »: the builds with a box to tick, the ticked ones in the order of their start levels (each in a field, with the levels it applies to), the merged guide as a track of named segments, the checks (what blocks stands out, what only warns doesn't), the name and the author, and **Merge N builds**, greyed while something blocks.

## Reading the files

- **A gem in the wrong folder.** An id such as `Metadata/Items/Gems/SkillGemShieldWall` that exists in the other folder (`Gem/`) could show « did you mean… » in the warnings, once the editor can fix it. After 1.0, which will rename gems, the card of an unknown gem could also offer the nearest known one (« Did you mean Frost Bomb? », the owner's idea of 2026-11-20 at 2j3b): a rule that reads the data, measured on the corpus first.
- **A text of any length** (an edge case, noted on 2026-11-21 at step 2k2; depends on: the cards on hover of step 4, and the reading of the files): the format sets no limit on `additional_text`, `description`, `name` or `author`, nor on the size of a file or its number of entries (the documentation of Grinding Gear Games, read on 2026-11-21); the corpus goes up to 762 characters for a hint, 1,160 for a description, 72 KB for a file. The cards on hover have no maximum height, so a long hint would run off the screen (a lead: the height of the window less a margin, the text of the author scrolling in the card, which stays open under the pointer); a file of megabytes from a stranger is bounded nowhere (a question for the security audit). What the game does with a long text in its tooltip isn't known.
- **A whole number larger than 64 bits is written back with a fraction** (an edge case, noted on 2026-11-22 at the review of 4b; depends on: the download of step 7): `123456789012345678901234567890` in a field the format doesn't name is written `1.2345678901234568e+29`, since `serde_json` reads a number out of `u64` and `i64` as an `f64`; none in the corpus. Its feature `arbitrary_precision` would keep it, but breaks the numbers read through `#[serde(flatten)]` and `untagged`: to measure before choosing.
- **Two hints of a slot whose texts start with the same line are one hint** (an edge case, noted on 2026-11-22 at step 4c; depends on: the inventory of step 6): a hint without a unique is named by the first line of its text, so the life flask and the mana flask of a guide of Mobalytics, both in `Flask1` and both starting with « Author stages: 1-5 opening », are read as one hint with two texts; when both go at 20, « N changes » counts one hint, not two (one build of the corpus of 32). Their place (`slot_x`) would tell them apart, but not the charms of `Charm1`, which the tools place differently: to measure with the drawing of the slots.
- **A level that isn't a whole number refuses the whole file** (an edge case, noted on 2026-11-22 at the review of 4c; depends on: nothing): `[-1, 5]`, `[1.5, 5]` or `[1.0, 50.0]`, which a tool in Python may write for levels kept as floats, is a value of the wrong type, and the build doesn't open, while `[101, 130]` is only a warning. A third form of `LevelInterval` that keeps the value as it is written, read as invalid and written back without loss, would open the rest of the build; to decide then whether `[1.0, 50.0]` is 1 to 50. None in the corpus.
- **A file saved in UTF-16 is refused as not text** (an edge case, noted on 2026-11-23 at the review of 4e2; depends on: nothing): Windows PowerShell 5.1 writes UTF-16 LE with its byte order mark `FF FE` by default (`>`, `Out-File`), so a JSON copied from poe.ninja and saved that way is refused with « it isn't text », when its owner holds a text. A lead: read UTF-16 after its byte order mark (`String::from_utf16` on the pairs of bytes), about 15 lines and two tests in the core. None in the corpus.
- **A text that ends too soon, said so** (polish, noted on 2026-11-23 at step 4e3; depends on: nothing; a change of the core, critical code, so reviewed again until no high or medium finding is left): a copy or a download cut short is refused as any JSON that breaks, « isn't valid JSON at line 7 » with its last line, where the mock-up says « That isn't the JSON of a whole build: it stops at line 7. ». The core would tell the end of the text from another error (`serde_json::Error::classify`, `Category::Eof`) in a field of `ReadError::NotJson`, about 15 lines and two tests in `read_error.rs`, and the bridge would pass it on.
- **Files dragged over the field of Paste JSON** (polish, noted on 2026-11-23 at the review of 4e3; depends on: the mock-up first): the grid of the page lights up, but the field neither lights nor says « Let go to open it » as the zone does; once dropped, the zone comes back and opens them or says why.
- **An image pasted in the field of Paste JSON** (an edge case, noted on 2026-11-23 at the review of 4e3; depends on: nothing): a paste without text, an image copied, is read as an empty text and refused as « This text isn't a build: an object with a name ». A paste without text could say nothing, or say that it holds no text.
- **A Ctrl+V anywhere on the first visit** (polish, noted on 2026-11-23 at step 4e3; depends on: the field of Paste JSON, 4e3b): a JSON pasted on the page, without a click on Paste JSON first, would open as it does in the field; the paste of the keyboard asks the browser no permission there either. Not in `specs.md`: a paste in a field of the page (later, the editor) must stay the field's.
- **The meaning of a single-number `level_interval`.** Read as « from that level to 100 » until checked in the game.
- **Three tags of the markup the mock-up doesn't know** (found at 2j5, 2026-11-20): `silver` (11 tags in 3 files of the corpus), `unique` (11, in 1) and `bronze` (3, in 1), shown as plain text with their brackets. Check in the game which colour or font each one is, and add them to the markup of the author's texts (step 4). Depends on: nothing.

## Deployment

Set aside at step 3 (Claude Code, 2026-11-22), see [cloudflare-usage.md](cloudflare-usage.md):

- **The header Strict-Transport-Security** (security; the owner, 2026-11-22, at step 3; for the security audit before version 1): Always Use HTTPS is on (checked: a 301 from `http://`), but a browser still asks over HTTP once before the redirect; the header makes it go to HTTPS straight away for its duration. Once sent, a browser refuses HTTP to the domain until it expires: start with a short `max-age`, and add `includeSubDomains` only if every subdomain of `sylent.tools` serves HTTPS.
- **A content security policy** (security; for the security audit before version 1): a header `Content-Security-Policy` that lets the page load its own files only, so that a script slipped into a build's text can't run. It needs `'wasm-unsafe-eval'` for the core and the hashes of the inline scripts of SvelteKit (its option `kit.csp`), so it is decided with the audit, once the interface draws the texts of strangers (step 4).
- **A page 404** (polish; depends on the addresses of the website, specified with the library or the short links of version 3): today an address that doesn't exist gets the plain answer of Cloudflare for a missing file; the website has one page, so no link leads there yet.
- **The website on the owner's VPS** (an idea of the owner, 2026-11-22, at step 3; depends on the VPS with Coolify the owner plans to buy): serve the static website from it rather than from Cloudflare. To weigh then: a static website costs nothing on Cloudflare, with no machine to keep up, the reason a VPS was rejected (`docs/technical-choices.md`, Host); worth it if the VPS hosts the server of version 3 anyway, or if Cloudflare limits the website (`docs/cloudflare-usage.md`, Risks). The move is the workflow of deployment and the DNS record of `pathweaver.sylent.tools`, the files unchanged.
- **A preview of each pull request** (method; depends on nothing, costs a workflow and the secret on the pull requests): a version of the website at an address of its own, to try a branch on the phone before the merge. The pull requests come from the owner alone, who tries them on `npm run dev`; worth it once a tester tries the branches.
