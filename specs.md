# Specifications

What Pathweaver does, as the user sees it. Version 1 was specified at step 0 of [roadmap.md](roadmap.md) on 2026-11-16, from a corpus of 32 real `.build` files (see [docs/build-files-in-the-wild.md](docs/build-files-in-the-wild.md)); the later versions are specified when their turn comes.

## Purpose

Path of Exile 2 reads `.build` files in its Build Planner since version 0.5: a JSON file that lists the passives, the skill gems and their supports, and hints on the inventory slots, each for a range of levels of the character. Guide sites and tools (poe.ninja, Maxroll, Mobalytics, Path of Building converters) export them; the only way to see what a file holds, before putting it in the game folder, is to read its JSON.

Pathweaver (the build viewer and planner of Path of Exile 2: the subtitle that goes with the name everywhere, so that it is found by those who search for a build planner) shows a `.build` file as a player reads a build: its passive tree, its skills and its gear, at each level of the character. Later, it edits them; then, in version 3, it hosts them for everyone to share.

## Design principles

- **The `.build` file is the native format.** Not an export of a format of our own: a file opens whatever tool made it, and is written back without losing a field another tool put in it.
- **Level by level.** A build is a progression: the interface follows a level of the character, not separate profiles.
- **A personal tool first.** Versions 1 and 2 serve the player who uses them: no account, no server, a static website; nothing leaves the browser: a build is shared as its `.build` file.
- **The rules in Rust, once.** The reading, the checks, the levels, the merging and the passive tree are in the core, so that the same code checks a file in the browser and, in version 3, on the server.
- **The game data come from the game; so do the portraits and the passive tree.** The names and the stats come from the data of the game, never typed by hand (see [docs/game-data.md](docs/game-data.md)). The images of the game are the portraits of the classes and ascendancies, so that a build is recognized at a glance, and the icons and frames of the passives, which give the tree its charm (the owner, 2026-11-18); the other shapes and marks are drawn for Pathweaver.
- **The documentation of Grinding Gear Games wins.** When the files in the wild disagree with the [documentation of the format](https://www.pathofexile.com/developer/docs/game#buildplanner), Pathweaver follows the documentation, and still reads the file.

## Out of scope

- **A share link** (the owner, 2026-11-18): a link that holds the whole build is 1,936 characters for the median build of the corpus and 7,348 for the longest (its notes of the author), still 1,562 and 3,142 without them: no link to paste in a chat, where a Discord message stops at 2,000. A short link needs a server and a database: version 2. In version 1, a build is shared as its `.build` file, which a chat takes as an attachment.
- **Damage and defences.** A `.build` file holds no item, and computing a character is the work of Path of Building. Pathweaver shows what the build takes, not what it deals.
- **Phones and consoles.** Pathweaver is used on a computer (see [Screens](#screens)). On console, the game doesn't read local files: the players subscribe to builds on the website of Grinding Gear Games.
- **Translating the author's texts.** The name, the description and the hints of a build are shown as their author wrote them, in their language.
- **The images of the game, other than the portraits and the passive tree.** Gems and uniques are shown by their names and Pathweaver's own marks.

## Version 1

### Opening builds

- Three ways to open a build: drop one or several `.build` files on the page, choose them with a click on the drop zone of the home page or on the + of the band of the open builds, or paste the JSON of a build (poe.ninja offers to copy it). They open at once, without a button to confirm. The library opens builds too (see below).
- Several builds are open at once: a list shows them by name, one of them is shown. Opening a build adds it to the list and shows it; a build is closed from the list, which takes it off the list only: it stays in the [library](#library). Closing the build shown shows the one after it in the list, the one before it when it was the last, as the tabs of a browser do; with no other open, the library (My library), where the build closed stays (the owner, 2026-11-22), and the home page of the first visit until the library is built (step 8).
- The same build opened twice (the same content) isn't added again: the one already open is shown. The same content is the same fields with the same values, whatever their order in an object, the spaces and the line breaks between them (the entries of a list keep their order): the build pasted from poe.ninja on one line and its file, indented, are one build (4b, the owner, 2026-11-22). Each open build keeps its level while another is shown.
- A file that can't be read is refused alone, with its name and the reason: not text (bytes that aren't UTF-8, such as an image; measured as the file it is, never as a text three times larger), not JSON (with the number and the text of the line of the error, so that no one has to look for it; a line longer than 80 characters, a JSON pasted on one line, is cut to 80 around the error; for a file that ends too soon, a download or a copy cut short, its last line with text; the page says the number alone for a file, the owner, 2026-11-23), not a build (no `name`, not an object, or an empty file), a value of the wrong type or a field missing (with its place, such as `skills[2].support_skills[0].id`), larger than 1 MB (1,048,576 bytes; the largest file of the corpus is 72 KB). The other files dropped with it open.
- A byte order mark at the start of a file is skipped.

### The header of a build

- The name of the build, its author and its ascendancy (name and class, from the game data), and the file of the build to download (see Window layout).
- In About: its description, with the [markup](#the-authors-texts) of the game, and the `link` of the file (documented by Grinding Gear Games, usually the page of the guide), shown as a link that opens in a new tab, only if it is one address whole, by the rule of the addresses of the description below (4g2, the owner, 2026-11-24: `https://.`, an address followed by words or one with a hidden character is not); otherwise as plain text.
- The addresses an author writes in the description (2k3, the owner, 2026-11-21; one build of the corpus, an Amazon of Maxroll, writes its guide and its planner there, its `link` empty): each that starts with `https://` is a link where it is, drawn as a chip of its site, never in the letters of the author (4g3, its third review, the owner, 2026-11-24: in the letters of the author, a space of one pixel, a tag that changes nothing on screen or two colours the eye can't tell apart glued to a link made it read as another address than the one it opens, a new way at each review; plain text set aside): its site as the browser reads the address it opens (« maxroll.gg », without `www.` when a name with a dot follows it: `www.com` stays whole), in the accent, the weight of the text, on a tint of the accent, the colour of the text on hover, never the bold, italic, underline, colour nor size of the author, never cut across two lines: past 40 characters, the end of its site only, after « … » (« …0-5-5-leveling-and-endgame-gear.evil.io »), as the address bar of a browser cuts a long site, since its true domain is at its end and its start may be chosen to read as another (4g3, its fourth review, the owner, 2026-11-24: an ellipsis at its end hid the domain; the chip on several lines crowded the guide); its whole address in its tooltip; an address whose site the browser can't read stays text; an address is made of the visible characters of ASCII and ends at the first other one, a space, a hidden character or a letter beyond ASCII (4g2, the owner, 2026-11-24: a space without width or a mark that turns the direction of the text could show an address other than the one opened; the corpus writes none beyond ASCII), at a quote, at a change of style or a brace of the markup (`<u>{https://…}`; a tag that changes nothing, `https://a<r>{.com}`, leaves the address whole), never on a mark of punctuation that closes the sentence (`.`, `,`, `;`, `:`, `!`, `?`, `]`, and a `)` but one that closes a `(` of the address, `wiki/Foo_(bar)`). A chip is drawn in the order of its letters, from left to right, whatever the text before it (4g3, its review: a mark that turns the direction, written in the text just before a link, turned the link that opens `evil.io` to read `https://google.com/…`), and an author's text never turns the words drawn around it: the core removes from it the characters that move the text around them, the embeddings, overrides and isolates of Unicode (U+202A to U+202E, U+2066 to U+2069) and the separators of paragraphs of its algorithm of direction (U+2029, U+0085, U+001C to U+001E), which the corpus never writes (4g3, its second review: U+202B before a link drew the text before it at its right; U+2069 closed the isolate the page puts around the text); the strong marks U+200E, U+200F and U+061C, invisible letters that turn no Latin letter, stay. A description of spaces and such marks only is none. The guide is one link: the `link` of the file, the one its author named; when it has none, the first address of the description among its pieces shown (The author's texts), said to come « from the description » (the owner, 2026-11-21: one guide, not two links to the same site; the Amazon writes its guide, then its planner); the others stay chips in the text. Every link opens in a new tab that keeps no hold on the page, its whole address in its tooltip: a link from a stranger may lead anywhere (a question for the security audit). The addresses of the hints stay text (4g2, the owner, 2026-11-24): a card on hover can't be clicked, and the corpus writes none.

### The level

- The level of the character is chosen with a slider from the lowest level the entries of the build cover to the highest (1 to 100 for most, 65 to 100 for a guide of the maps; 2g2, 2026-11-19), and with **markers**: one at each level where the build changes, that is where what the file says the build holds differs from what it held at the level before (see What changes here below), passives aside: a passive that starts makes no marker, since a file can add one at every level (83 levels with a change on a build of the corpus, 14 markers without them); passives that stop (a respec) make one. A click on the track moves the slider there; at the lowest level of the build, nothing comes before it to compare with, so no marker.
- The levels a build covers are those its entries apply at (4c, the owner, 2026-11-22, at its review): an entry without a `level_interval` applies at every level, so covers 1 to 100, and a guide of the maps covers 65 to 100 only when each of its passives, skills and hints writes its levels (the only one of the corpus does); a support covers no more than its skill, an entry with an invalid interval none, and a build without a valid entry 1 to 100.
- **◀ and ▶** on both sides of the level go to the previous and the next marker, each with the level it goes to written under it; the keys ← and → do the same anywhere on the page of a build, without aiming at the slider first, but in a field, where they move the caret (the owner, 2026-11-19), and under a box over the page (What's next).
- An entry (a passive, a skill, a support, an inventory slot) applies at a level when:
  - it has no `level_interval`: at every level;
  - its `level_interval` is `[min, max]`: from `min` to `max`, both included (`0` counts as `1`, and a `max` above 100 stops at 100);
  - its `level_interval` is a single number `n` (allowed by the documentation, without its meaning): from `n` to 100. To check in the game.
  - an invalid interval applies at no level, and is listed among the [warnings](#unknown-and-invalid-entries): a `min` above its `max` or above 100, a single number above 100, a list that isn't two numbers (`[]`, `[5]`, `[1, 50, 100]`; 4c, the owner, 2026-11-22: none in the corpus, whose intervals are lists of two numbers but three single ones). A level that isn't a whole number from 0 to 4,294,967,295 (`[-1, 5]`, `[1.5, 5]`, `[1.0, 50.0]`, `"1-50"`) is a value of the wrong type: its file is refused, with its place (see [Opening builds](#opening-builds)).
- A build opens at the highest level it covers (100 for most).
- A build that is the same at every level (a snapshot of a character, from poe.ninja or Path of Building) has no marker; the slider says so: « A snapshot: the same at every level » over its track from 1 to 100, ◀ and ▶ alone and greyed, without « N changes » (2g2). Its page says nothing else of it (2k5, the owner, 2026-11-21: one knows what one opens, and the track says it already): no « New at N » in the right column, whose skills start at its top (« A snapshot: nothing changes » in its place set aside), no ring on the tree, nor « new at N » in its legend.
- **What changes here**: at a marker, each part (skills, tree, inventory) marks what starts at this level as new, and lists what stopped just before it as removed (for instance « − 34 passives » at a respec).
- **What changes at a level is read from the file alone** (the owner, 2026-11-18): what the build holds at the level, as its entries say, against what it held at the level before. An entry that stops and starts again the same at the next level (the same id, the same skill, the same note) changes nothing: a build of the corpus does this with 70 of the 81 supports it lists again at 71, which change nothing for the player. One that comes back with another note of its author is a change of its note. A slot is read as a list of hints, without their place: the three charms share one id (`Charm1`) and are told apart by their item, never by their position; a hint replaces another only when one leaves and one comes on its slot, since where several share it (the flasks, the charms) the file doesn't say which replaces which. The changes, by category:
  - skills: a skill comes (with its supports) or goes; a support comes onto a skill already there, or leaves one that stays;
  - passives: taken (shared, of set I, of set II, of the ascendancy: the weapon sets named « set I » and « set II », as the legend of the tree and the switches name them, the owner, 2026-11-20; the file doesn't say which passive is of the ascendancy: that group is read from the data of the tree, at step 5, and until then such a passive counts with those of its weapon set, 4c, the owner, 2026-11-22), given back;
  - gear: a hint comes, replaces another, goes;
  - notes: an entry set again with another note of its author (on a gem) or another text (on a hint).
  A gem, a hint or a note counts as one change, each group of passives as one; a note that comes with an entry marks it rather than counting.
- **What the build holds is read thing by thing**, never entry by entry (4c, the owner, 2026-11-22, measured on the corpus): a skill by its id, a support by its id and its skill, a passive by its id and its weapon set (a `weapon_set` other than 1 or 2 is both sets), a hint by its slot and its item: its unique, or else the first line of its text as its author wrote it, markup included (read without its markup, no marker and no count of the corpus changes). A thing that two entries set at the same level is held once, with the notes of both, each note once, in the order of the file, and compared whatever the order of its entries (a gem listed again with a note it had changes nothing): the same passive listed twice (226 times in the files of Mobalytics) changes nothing, and the same skill in two entries (once, a conversion from Path of Building) is one skill with the supports of both. A note is compared without the spaces around it.

### Skills

Step 4 of the roadmap.

- The skill gems that apply at the level, each with its supports under it, in the order of the file. A support is shown when both it and its skill apply, and its levels are those where both apply: a support set from level 1 under a skill that comes at 59 is new at 59, never « from the start » (2k, the owner, 2026-11-20).
- Each gem shows its name from the game data, with a mark whose shape says its kind and whose colour says what it is: a skill a hexagon, its top facet lighter, a support a square on its tip, told apart by their shape as well as their colour (2g3, the owner, 2026-11-19, of twelve marks); a skill in the colour of its attribute (strength, dexterity, intelligence), a spirit gem, a skill, in a teal of its own, a lineage support, a support, in a warm grey of its own (2j2, the owner, 2026-11-20: a shape of their own would have broken the rule of the kinds), a gem without an attribute in the cool grey; a gem shared half and half between two attributes (114 gems of the game, which RePoE colours « w » as a gem without one, but whose `requirement_weights` say the two; 23 builds of the corpus of 32 hold one: Pounce, Herald of Ice, Freezing Mark, the grenades…) its shape cut down the middle, its left half in the colour of the first attribute in the order of the game (strength, dexterity, intelligence), its right half in the other, the lighter top facet over both (2kb, the owner, 2026-11-20: of three ways, a colour of its own for each pair, which would have added three to learn, one close to the teal of the spirit gems, and the cool grey, which told them wrong), a gem that leans to one attribute (25/75, Malice) in its colour, a spirit gem in its teal whatever its attributes, the one gem of three attributes in the cool grey; the skill a spirit gem triggers, which the file lists among its supports (Comet under Cast on Critical), is a skill; never under 10 pixels, where the shape is lost. The data say which gems are lineage supports (`is_lineage` in RePoE: 88 of 642 supports, in 11 files of the corpus of 31).
- On hover of its mark, or of the name of a skill: a card in the language of the card of a passive, which does not follow the pointer (the owner, 2026-11-20): above a support, just over its mark, where the eye is (left of the column, it was 300 pixels from a mark at the right of a row), never over its own row, so that the pointer goes from one support to the next, under it when there is no room above, opaque since it lies over the rows; beside a skill, its mark or its name at the left of the column, just left of the column, over the tree rather than over the rows, see-through as the card of a passive. In the construction of the cards on hover (Window layout): its name, its tags as the game names them as its subtitle, without its kind for now (« Skill gem », « Spirit gem », « Support gem », « Lineage support »: the owner, 2026-11-20, will see how to bring it back), its icon at the right; in its body, its description from the game data and its levels with the word written out (« New at level 59 », in the word of « New at N », « From level 23 », « From the start », and where it stops when before 100: « From level 15 to 64 », « New at level 59, until 70 »), the levels of a support those where both it and its skill apply; then the hint of the author (`additional_text`), with its markup.
- Two lines of the same skill with different intervals (the same gem from 1 to 5, then from 6 to 14 with more supports) are two entries: at a level, only the one that applies is shown.

### Passive tree

Step 5 of the roadmap.

- The whole passive tree of the game, at the positions of the game, drawn with the icons and frames of the game for each kind of passive (small, notable, keystone, jewel socket, ascendancy), in colour when taken and greyed when not (2i, the owner, 2026-11-19); moved with the mouse and zoomed with the wheel. The icons show as soon as the frame of a small passive is 2 pixels wide, that is at nearly every zoom; zoomed out further, the passives are the dots of the style. The masteries of the export are only the art at the centre of a group, never taken nor linked: they aren't drawn (their art waits in [docs/backlog.md](docs/backlog.md)).
- At the level chosen: the passives the build has taken up to this level are lit; the passives it takes later are shown faded, their links solid in a faint colour, without dashes (the owner, 2026-11-19); the others are dimmed.
- The ascendancy of the build, with its passives, at the centre of the tree, in the empty disc inside the ring of the class starts (the owner, 2026-11-19), not in a box of its own: every ascendancy shrunk alike to 85 % around the centre of its box, so that the largest (Monk3) fits with room to spare, over the portrait of the ascendancy, large (about 300 pixels), in colour at 40 % (the owner, 2026-11-20). It isn't linked to the start of the class, since the export of the tree links them nowhere. The tree opens framed on the passives of the build, its ascendancy included.
- The weapon sets: the passives with a `weapon_set` of 1 or 2 belong to that set, the others (`weapon_set` 0 or absent) are shared. Both sets are drawn together (the owner, 2026-11-19): the links between shared passives in white, those of the passives of set I alone in red and of set II alone in green, as the game draws them (Path of Building, `PassiveTreeView.lua`), Vivid red `#ef4444` and Vivid green `#22c55e`; the set chosen with the switch strong, the other at 35 %; on a switch, the two swap their strength in 180 ms, the colour of the buttons in 120 ms (S1 of three, the owner, 2026-11-20: a wave lighting the set from the shared passives and a flash of its links set aside).
- On hover, a passive shows a card beside it, on the side of the tree with more room (B of three, the owner, 2026-11-20: a card that follows the pointer and a panel fixed under the legend set aside): in the construction of the cards on hover (Window layout), without art: its name, its kind as its subtitle (« Notable », « Ascendancy · Notable »); in its body, its stats from the game data (a keyword in brackets, `[Spell]` or `[Critical|Critical Hit]`, shown as its words), its state at the level (« Taken at level N », « Taken later, at level N », « Not taken »: the word « level » written out, the owner, 2026-11-20) and its weapon set; then the hint of the author, with its markup (The author's texts). It stays when the pointer goes straight from one passive to the next.
- The number of points the build has spent at the level: passives, ascendancy points, and those of each weapon set.
- What is new at the level is ringed in the accent on the tree, without a count beside it: « New at N », at the top of the right column, lists them (the owner, 2026-11-19).

### Inventory

Step 6 of the roadmap.

- The inventory of the character laid out as in the game: weapons and offhands of both weapon sets, helmet, body armour, gloves, boots, belt, amulet, rings, flasks, charms.
- A slot with a hint at the level is marked; on hover or click, it shows the hint and, when it names one, the unique item (`unique_name`) with its kind, its base and its stats (the game data don't say the stats of a unique: they come from Path of Building, see [docs/game-data.md](docs/game-data.md)); its card is in Window layout.
- `slot_x` and `slot_y` say which cell of a slot with several cells the hint is for.
- Two writings of a slot the drawing has are drawn in the cell the other files write (2k2c, the owner, 2026-11-21): the mana flask in `Flask2` (Path of Building, poe2-tools) in `Flask1`, cell 1, as Mobalytics and Maxroll write it; a charm in `Trinket1` (Maxroll, cells 2 to 4) in `Charm1`, its cell less 2, when the game data know its item as a charm (a free text stays in the list). The rule is measured on the corpus before it is coded ([docs/backlog.md](docs/backlog.md)).
- A `.build` file holds no item: an empty slot is just a slot the build says nothing about.

### The author's texts

- The description and the hints (`additional_text`) are shown with the markup of the game, as the documentation of Grinding Gear Games writes it (read on 2026-11-24, which names it for the hints only; the corpus writes it in descriptions too): `<tag>{text}`, nested; line breaks (`\n` or `\r\n`) are kept. Its tags:
  - the fonts: `r` regular (neither bold nor italic), `b` bold, `i` italic, `u` underlined;
  - the sizes: `s` small, `m` medium, `l` large, each a factor of the size of the text around the author's text, so that a size inside a size doesn't grow again: `s` 1, `m` 1.15, `l` 1.35 (4g1, the owner, 2026-11-24). The authors of the corpus write a head in `m` over a text in `s` (Maxroll) or without a size (Mobalytics, Grinding Gear Games), so `s` is the text, never smaller (Maxroll's notes would be 10.8 pixels in a card), and no author writes `l`; `m` a step above, its head told by the bold or the colour that always comes with it in the corpus, and under the title of a card (13.8 pixels in a card, under its 14; 1.25 would set the head of a note over the name of what carries it);
  - the fourteen named colours: `white`, `grey` (or `gray`), `black`, `red`, `orange`, `yellow`, `green`, `blue`, `indigo`, `violet`, `bronze`, `silver`, `gold` and `unique`, the gold of a unique item; `purple`, `cyan` and `magenta`, which it doesn't name and the corpus never writes, are tags it doesn't know;
  - a colour `rgb(r, g, b)`, each value 0 to 255.
  - a tag is read whatever its case and the spaces around it (`<GOLD>`, `< gold >`, `RGB(`; 4g2, the owner, 2026-11-24): perhaps more than the game reads, and harmless; the corpus writes lower case only.
- A tag Pathweaver doesn't know, or a brace left open, is shown as plain text, as written. Every brace pairs, after a tag it knows or not (4g2, the owner, 2026-11-24; none in the corpus): `<b>{<purple>{x} y}` is « <purple>{x} y » in bold, and a brace of the author never ends the style around it; a closing brace with no brace open is plain text. The texts of a file are never read as HTML: a file from someone else is untrusted.
- An author's text, a description or a note, is shown up to its 1,000th piece, a text in one style, a link or a line break, never cut in two; past it, « … » in the weak grey follows, a space after the last piece, none after a line break, where it would only indent « … » (4g3b, its review), without a tooltip (4g3b, the owner, 2026-11-24: the page drew a megabyte of a letter and a line break, 699,028 pieces, in 3.5 seconds, where the longest description of the corpus has 27). The links of a description count among its pieces, and its guide is the first address among the pieces shown (4g3b, its review, the owner, 2026-11-24: a link the page doesn't show never becomes the guide).
- The colours are the author's (the owner, 2026-11-20): a note written in grey stays grey, one in gold stays gold, as the game shows them; the author tells what matters from what doesn't, and a note without a colour is in the colour of the text.
- An author's colour stays readable on every style (the owner, 2026-11-20: a navy blue would vanish on a dark card, and the yellow and the gold of the corpus on the light one, Frost), its hue kept: the author meant « blue », not « unreadable »:
  - the named colours (`grey`, `gold`, `red`…) are tokens of each style, a light gold on Frost Night and a dark one on Frost, tuned on Frost Night (2n4, and 4g1 for `indigo`, `violet`, `bronze`, `silver` and `unique`: each at 4.5 to 1 or more on the band, the lightest surface a text of the author shows on), the other styles after version 1 (The style); `black`, unreadable on a dark card (1.1 to 1), is the darkest neutral grey at 4.5 to 1 there, a little darker than `grey`, as `rgb(0, 0, 0)` would be lightened (B2 of three, the owner, 2026-11-22);
  - a colour `rgb(r, g, b)` whose contrast is under 4.5 to 1 (the threshold of a small text) on the surface the named colours are tuned on, the band on Frost Night (the token `--markup-surface`, 4g3: the lightest surface a text of the author shows on, so readable on every darker one), is lightened on a dark surface, or darkened on a light one, just enough to reach it, each channel moved by the same share toward white or black so that its hue is kept: `rgb(0, 0, 0)` becomes `--markup-black`, `rgb(128, 128, 128)`. Measured on the corpus (32 files): 91 tags `rgb(…)` in 3 files, all readable on Frost Night, several too light for Frost.

### Unknown and invalid entries

- An id that matches nothing in the game data (a passive, a gem, a unique, an ascendancy, a slot) is shown where it is with its raw id and an « unknown » mark, and listed in a **warnings** panel by part, with the version of the game data Pathweaver uses. A file made for another version of the game is the usual cause: Path of Exile 2 1.0 (2026-12-11) will rename and remove some.

### Library

Step 8 of the roadmap.

- The library holds every build opened in this browser; the list of open builds holds those at hand. Opening a build adds it to both; closing it takes it off the list of open builds, never out of the library.
- The open builds are open again at the next visit, with the level each was shown at.
- The home page lists the builds of the library, the last opened first; one opens from there, or is removed from the library for good, which closes its tab when it is open. Once the last build is removed, the home page is the first visit again.
- The builds are kept only in this browser, on this computer. When the browser refuses to keep them (private browsing), Pathweaver works the same and says that nothing will be kept.

Download .build keeps the file of a build. »; at the first visit, the foot of the page says it in place of « Your builds stay in this browser. Nothing is sent anywhere. ».
- **Download .build** answers in a box under its button: where the game reads the file (see Downloading a build).

### The style

- **Frost Night is the reference style, and the only one of version 1** (the owner, 2026-11-18; alone, the owner, 2026-11-21: one style is enough for a first version): dark, a blue black, one blue. Every colour of the application goes through a token, so that another style is only a set of values. Frost (light) and Ember (amber on a neutral grey) come after version 1 ([docs/backlog.md](docs/backlog.md), Styles), derived from it, the light one in a pass of its own, since a shadow, a texture or a grey portrait don't carry over as they are.
- **Manrope for every role** (the owner, 2026-11-18, among 85 fonts): the text, the titles (600, spaced -0.02 em) and the numbers, which take its figures of one width so that the levels line up; the name alone in Archivo (see The brand), and the big titles of the home page and of the library with it; the code (a pasted JSON, the line of an error) in the monospace font of the system.
- **The colours of a change** (the owner, 2026-11-19, those of the rise, the warning and the fall of Exile Market, tuned together on a blue night): what comes `#5fcf80`, what replaces another `#f0b85a`, what goes `#e66a5c`, on the signs only, apart from the red of the errors and from the colours of the attributes.
- **The colours of the gems**: of the attributes as in the game (the owner, 2026-11-19, those of Exile Market), strength `#e0473f`, dexterity a true green `#3fbf4f`, intelligence `#5aa7f0`, apart from the green and the red of a change; a spirit gem a bright teal `#2dd4bf`, a lineage support a warm grey `#c2b8a3`, a gem without an attribute the cool grey `#8393ad` (2j2, the owner, 2026-11-20, of five teals and three greys).
- **The graph paper at 3 % everywhere** (the owner, 2026-11-18): behind the blocks, the bands and the tree, and on the home page, the first visit and the library alike; its colour and its size are settled in the first component where they matter, from 2f (the owner, 2026-11-18: one component at a time, from top to bottom).
- **The design system** (2n4, 2026-11-22): the values are the tokens of the mock-up, `docs/mockups/pathweaver/css/tokens.css`, the reference, copied once into one style sheet of the application, which the canvas of the tree reads too; a component uses nothing else, so that a colour or a size changes in one place. The roles and the rules:
  - **Colours by role**: the surfaces (the page, the bands, the deep shade of the level band, of the windows that hang under a control and of the heads of the cards, the right column a shade darker, the body of a card a step darker than its head); the text, the weak grey of what is secondary, the white of a flash; one accent, for what is new, the links, the markers of the level and the focus; the red of the errors, apart from the red of strength; the colours of a change, of the attributes, of the weapon sets, the gold of a unique, the yellow of an unknown id, the named colours of the author's markup. A colour never says a thing alone: a sign goes with the colour of a change, a shape with that of a gem, words with an error.
  - **No borders** (the owner, 2026-11-17): the blocks are told apart by their shades; a thin line only between the parts of a text in a card.
  - **Sizes**: the minimum width 900 pixels, one message under 600 (Screens); the wide layout of each view from a window of 1,600 pixels; a tab of a build 668 pixels high, the window at 960 × 1,080 under its bands; the text at 14 pixels, 12 or 13 in the right column and the cards, 10 or 11 for the small capitals; square corners, 3 pixels for the windows that hang under a control and the cards on hover, 4 for a box over the page, round portraits.
  - **Motion**: what opens or springs goes a little past its end and comes back; what slides slows to its end; a link changes its colour in 0.3 s, a card fades in 120 ms; every motion stops, or happens at once, when the system asks for less motion.
  - **Focus**: a ring of 2 pixels in the accent inside every control, shown when it is reached with the keyboard; the cursor of the level draws its own (The level).
  - **Contrast**: the texts at 4.5 to 1 at least on their surface, the button that confirms a removal raised to 4.8; a few small secondary texts tuned by eye stay under it, kept by the owner (2026-11-21).
  - **Icons and images**: Pathweaver's own icons, drawn in SVG by the code (the mark, the note of an author, the marks of the gems, the sticky note « ? »); from the game, only the portraits of the ascendancies and the icons and frames of the passives ([docs/game-data.md](docs/game-data.md)).
  - **The tone of the messages**: short and plain, in English for version 1; a message says what happened and where (« That isn't the JSON of a whole build: it stops at line 7. »), and addresses the player as « you ».

### The brand

Decided by the owner on the mock-up (step 2, 2026-11-17), its reference.

- **The mark**: the owner's own, two rings of a triangle pointing down, the outer one in three bars, the inner one a P, every edge flat or at 60°; in its bold weight (bars a little wider than the gaps). Its frame is in the accent, its P in the colour of the text around it.
- **In the band of the site**: the mark at 24 pixels, then « Pathweaver » in Archivo 700, spaced -0.06 em, at 16 pixels, 8 pixels apart, the middle of its capitals 1 pixel below the middle of the mark, tuned by eye.
- **The favicon**: the same mark, an SVG drawn at 16 pixels, its frame in the accent, its P dark or light after the scheme of the system, as the browser draws its tabs.
- Set aside: the weights as drawn, even and light, the mark on the pixel grid (sharper at 16 pixels, but a second drawing), the P alone, the mark on a square of the accent, the frame or the whole mark in one ink.

### Languages

- Version 1 is in English. Every text of the interface is in the translation file of English, none in the code, so that French is added in version 3 without touching the code; the game data are loaded per language for the same reason.
